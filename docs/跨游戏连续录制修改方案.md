# 跨游戏连续录制修改方案

## 目标

同一次陪玩服务内，用户退出游戏 A 后可以在保存弹窗选择「继续录制」，把等待和打开游戏 B 的过程录下来。用户切到 B 时，录制恢复为 B 的游戏采集。整次录制保存为一份 MP4。

设置增加全局开关「游戏退出后可继续录制」，默认关闭，旧配置缺少该字段时也按关闭处理。开启后，每款游戏退出时仍由用户在弹窗确认是否录桌面。空闲时仍由已启用的游戏窗口触发开录，无需手动开始，也无需接入陪玩服务状态。

## 现有逻辑与冲突

| 现有逻辑 | 对本次需求的影响 |
| --- | --- |
| `recorder::run` 在当前游戏的匹配进程全部退出后停止输出，`finalize` 保存文件并将它加入待命名队列。 | 弹窗打开时 OBS 输出已经结束。要在同一文件里继续，需先暂停输出并弹出选择，等用户结束时再执行最终保存。 |
| `Session` 只保存一款游戏，它同时用于查找捕获目标、托盘状态和文件名。 | 会话需要分别保留首款游戏和当前游戏。接力只更新当前游戏，命名和崩溃恢复继续使用首款游戏。 |
| 当前游戏还有匹配进程时，另一款游戏只触发通知。空闲时按游戏列表顺序找启动候选。 | 当前游戏优先规则可以保留。桌面接力是独立的选取时机，由合格的前台窗口触发，列表顺序只用于解决同一个窗口同时匹配多条游戏配置的情况。 |
| 全屏捕获要求游戏 HWND，显示器画面和该窗口的应用音频一起创建。同一显示器的窗口变化会被 `Target::Mon` 的相等判断跳过。 | 桌面段需要仅凭缓存的显示器标识建立画面源。全屏游戏段需要分别跟踪画面所用的显示器和音频所用的窗口，即使两款游戏在同一显示器上。 |
| 手动结束、跳过或磁盘空间不足后，只抑制原游戏的自动开录，其他游戏可能随即开录。 | 启用新模式后，终止整次录制时需要记录当时所有已经运行的已启用游戏，避免用户刚结束就自动开始录后台游戏。 |
| 托盘和设置页通过是否存在游戏名判断录制状态。保存弹窗处理的是已经落盘的待命名文件。 | 需要显式表达录游戏、暂停等选择、录桌面和空闲。保存弹窗需要识别正在等待选择的会话，同时仍能处理原有待命名文件。 |

相关实现见 [recorder.rs](../src-tauri/src/recorder.rs)、[main.rs](../src-tauri/src/main.rs)、[save.html](../ui/save.html) 和 [settings.html](../ui/settings.html)。

## 状态与操作

下表适用于开关已开启的录制。开关关闭时，游戏退出后沿用现有的保存和待命名流程。

| 当前状态 | 触发条件 | 行为及下一状态 |
| --- | --- | --- |
| 空闲 | 现有自动开录条件满足 | 创建一次会话和一份 MP4 输出，进入录游戏。 |
| 录游戏 | 当前游戏仍有匹配进程 | 按该游戏进程优先级选窗口。其他游戏打开或切至前台时仅按现有规则提醒。 |
| 录游戏 | 确认当前游戏的匹配进程全部退出 | 暂停输出的画面和声音，进入等待选择。打开保存弹窗，提供「保存」「不保存」「继续录制」。 |
| 等待选择 | 用户点击「继续录制」 | 用当前游戏最后所在的显示器准备桌面源，移除游戏音源，沿用麦克风配置和静音状态。关闭弹窗并恢复原输出，进入录桌面。 |
| 等待选择 | 用户一直没操作 | 保持暂停，无超时。下一款游戏打开或切到前台也不自行恢复。 |
| 等待选择 | 用户点击「保存」「不保存」或关闭弹窗 | 「保存」按输入的文件名收尾。「不保存」沿用二次确认和移入回收站。右上角关闭或 Alt+F4 按默认名保存，不再次弹出同一份录像的保存询问。 |
| 录桌面 | 用户切到某款已启用游戏，且前台窗口符合游戏窗口条件 | 在原输出中改录该游戏，进入录游戏。该游戏退出时再次暂停并弹窗。 |
| 等待选择或录桌面 | 已授权的桌面显示器无法建立捕获，或录桌面期间显示器不可用 | 提示原因，按默认名保存已录内容，结束会话。 |
| 录游戏、等待选择或录桌面 | 托盘「结束录制并保存」「跳过本次」或磁盘可用空间低于 1 GB | 托盘结束沿用待命名确认，跳过沿用现有语义。低磁盘保存已录内容，清除本次继续录制的选择状态。 |

### 多游戏与画面选择

- 一款游戏的多个进程仍属于同一游戏。例如 LOL 对局窗口退出但客户端进程仍在时，继续按优先级切回客户端。进程仍在但暂时没有合格窗口时保持当前游戏归属。进程枚举失败应与确认进程全部退出区分，避免误弹窗。
- 识别桌面接力时，用前台窗口及其进程判断用户切到了哪款游戏，再用该游戏的既有进程优先级挑选实际录制窗口。新打开和已在后台运行的游戏都可以接力。停留在桌面、切到未启用的游戏或只出现未就绪进程时，保持桌面录制。只在桌面段判断是否要自动改录另一款游戏。
- 接力后使用新游戏生效的录制范围，优先用单游戏覆盖配置，其次用全局范围。全屏游戏段采集该游戏所在显示器并只录该游戏的应用声音。桌面段采集上一款游戏最后所在的单块显示器，只保留麦克风，麦克风关闭或静音时该段没有声音。
- 在窗口捕获模式下也要刷新最后已知显示器，处理窗口 HWND 不变但移到另一块屏幕的情况。进入桌面段后固定该屏幕，直到接力成功或会话结束。
- 手动结束、弹窗决定结束和低磁盘等终止场景都按同一规则恢复自动开录。终止时已运行的已启用游戏分别进入抑制集合，观察到某款游戏的匹配进程全部退出后，才解除该游戏的抑制。终止时未运行的游戏按原启动条件开录。开关关闭时仍沿用现有单游戏抑制逻辑。

### 文件与用户状态

- 从首款游戏开始到最终收尾使用同一 `ObsOutputRef`、临时目录和分片 MP4。保存目录、命名模板、录制配置、麦克风设备、输出画布和编码参数从开录时确定。游戏接力只适配画面和音源，各段以同样的输出尺寸编码。
- `${game}` 取首款游戏名，`${time:…}` 取首次开录时间。`game.txt`、`tpl.txt` 和当前会话目录继续供异常恢复使用。正常保存、重名避让、回收站和异常退出后找回已录部分，复用现有路径。
- 托盘及设置页分别显示「正在录制游戏」「已暂停，等待选择」「正在录制桌面」。暂停时托盘停止闪红，仍保留结束和跳过入口。进入桌面段后恢复红点，并提示正在录制上一款游戏所在屏幕。

## 修改范围

| 位置 | 修改内容 |
| --- | --- |
| [config.rs](../src-tauri/src/config.rs) | 为新开关添加向后兼容的默认值。开录时读取开关和会话配置，录中修改从下次开录生效。 |
| [recorder.rs](../src-tauri/src/recorder.rs) | 增加等待选择、录桌面状态。区分首款游戏、当前游戏和捕获目标。实现暂停恢复、前台接力、会话结束抑制及异常收尾。 |
| [win.rs](../src-tauri/src/win.rs) | 增加前台窗口识别，复用既有窗口和显示器枚举。把进程枚举失败传给录制状态机。 |
| [main.rs](../src-tauri/src/main.rs) | 将录制阶段传给托盘、设置页和弹窗。将弹窗动作交给录制线程处理，用会话标识拒绝重复或过期的操作。 |
| [save.html](../ui/save.html) | 增加当前会话等待选择的模式，此时显示「继续录制」。待命名文件仍走原有模式。两者同时存在时先处理当前会话的选择，旧条目继续留在队列。 |
| [settings.html](../ui/settings.html)、[README.md](../README.md) | 增加开关和状态说明。明确何时录桌面、录哪块屏、如何结束，以及暂停等待期间不录制。 |

## 实现约束

1. 先暂停成功，再显示弹窗。点继续后先准备已授权显示器的画面并解除旧游戏音源，确认弹窗已隐藏，再恢复输出，避免把选择弹窗录进去。切换游戏时画面与应用音频应作为一次状态变更处理，切换失败且桌面源仍可用时维持已授权的桌面录制并重试，成功后再更新托盘状态。
2. 现有 `FragmentedMP4` 在 `libobs-simple` 中映射到 `ffmpeg_muxer`，OBS 32.1.2 的该输出声明支持暂停。实现时先在 Windows 上验证连续暂停、恢复、暂停中停止及音画同步。暂停、恢复或授权屏幕捕获失败时提示并安全收尾，只有确认输出已经停止后才移动或处理文件。尚未执行实机验证。[OBS 32.1.2 源码](https://github.com/obsproject/obs-studio/blob/32.1.2/plugins/obs-ffmpeg/obs-ffmpeg-mux.c)
3. 当前轮已触发终止时优先处理终止。本次会话后续到达的继续命令作废。继续、保存、丢弃和关闭的重复触发只能处理一次，已有待命名条目也不能被当前会话的操作误处理。

## 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 旧配置升级或开关关闭后退出 A | 沿用原来的保存弹窗和自动录制规则，无「继续录制」选项，也没有桌面录制。 |
| A 退出，无人操作或 B 已在前台 | 弹窗保持等待。已有视频帧、游戏音频和麦克风均未增加。右上角关闭后按默认名保存，只处理一次。 |
| A → 继续 → 桌面 → B → 继续 → 桌面 → A | 产出一份可播放的 MP4，沿用首次 A 的名称和开录时间。每次等待确认期间的音画均未写入。 |
| A 与 B 同时运行，或 LOL 从对局回客户端 | A 仍运行时 B 不抢占。LOL 的客户端还在时不会弹出继续选择。 |
| B 已在后台、尚无合格窗口，或用户切到未启用的 C | 桌面段继续。用户真正切到有合格窗口的 B 才接力。 |
| 只录窗口的 A 从主屏移到副屏后退出，B 在另一块屏幕接力 | 桌面只录 A 最后所在的副屏，B 按自身录制范围接力，整份文件尺寸固定。 |
| 全屏 A → 桌面 → 同一屏幕的全屏 B | 只在 A 段收 A 的应用音频，桌面段只保留麦克风，B 段恢复 B 的应用音频。麦克风的开关和托盘静音在各段均有效。 |
| 上一款游戏所在的显示器在点击继续前或桌面段断开 | 提示并按默认名保存，其他屏幕的桌面不会被录入。 |
| 用户结束、跳过、点弹窗保存，或录桌面时低于 1 GB | 本次会话按对应操作结束。当时已开的游戏不立刻开录，各自退出并重开后可再次触发。此时新启动的其它游戏仍可触发。 |
| 弹窗已有旧待命名文件、用户重复点继续，或暂停时 Aegis 异常退出 | 旧文件不受当前会话操作影响，同一选择只生效一次，重启后按首款游戏名恢复已录部分。 |
